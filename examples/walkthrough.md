# 从接手到写回

下面以[虚构 Atlas 项目](vault/projects/atlas/PROJECT.md) 为例，展示期望的使用方式。这是演示，不是实际 agent 测试结果。

## 1. 在新聊天接手

把示例库复制到临时目录，向 agent 提供复制后的绝对路径：

```text
使用 context-read，读取这个库里的 Atlas 项目。
告诉我现在做到了哪一步，以及下一步是什么。
```

期望得到：英文原型已完成示例检查，中文仍待验证，尚未部署。下一步是补充中文和混合语言样本。

不应得到：“搜索已经全面上线”，也不应仅因下一步里写了部署就去执行部署。

## 2. 保存一个阶段成果

假设后来用户提供了下面的结果：

```text
使用 context-write，记录用户反馈：今天中文检索的 6 个样例通过，
混合语言的 2 个样例失败。尚未部署，下一步排查混合语言分词。
```

期望更新项目现状与验证记录，保留“用户反馈”的来源和实际记录日期，不写成 agent 亲自测试通过。中文不再笼统标成未验证，混合语言的问题和未部署状态继续保留。

仅要求项目写回时，不必新建工作记录，也不必在总导航再写一份进度。若同时要求记录本次会话成果，再使用 `context-log`。

## 3. 检查状态矛盾

假设某段旧说明仍然写着“所有语言都未验证”：

```text
使用 context-review，整理 Atlas 的当前状态。
```

期望结合具体来源消除冲突，保留有效证据和未解决问题。仅修改文档不代表重新运行了验证，不能把整篇文件都标为当天已核验。

## 4. 保持主文档简短

方案讨论很长时，项目主文档保留最终决策、理由摘要、重新评估条件和专题入口，完整论证移到已有的决策文档。新 agent 从主文档开始，按问题查细节。

## 5. 查看跨项目的工作记录

示例库有两条虚构记录：[跨项目会话](vault/sessions/sess_11111111111141118111111111111111.md)与[通讯跟进会话](vault/sessions/sess_22222222222242228222222222222222.md)。

```text
使用 context-log，列出最近做过的工作，再只看 Atlas 相关的记录。
```

不筛选时，1 月 17 日的通讯跟进排在最前；筛选 Atlas 后，只剩关联两个项目的那一条。即使重新复制了文件，排序仍取属性中的时间，不取文件系统修改时间。

```text
使用 context-log，更新这次会话已有的工作摘要，保留之前的成果。
```

agent 应读取原记录，取得版本并合并新增成果。跨天更新保持同一 ID 和文件名；没有新内容就不改时间。要验证实际写入，请使用独立的示例库副本，不修改发布用样例。

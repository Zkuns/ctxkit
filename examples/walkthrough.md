# 不点名 skill 的日常工作示例

下面使用 [虚构 Atlas](vault/projects/atlas/PROJECT.md) 和 [虚构 Beacon](vault/projects/beacon/PROJECT.md)。这是行为演示，不是实际模型测试结果；日期和成果均为示例。

## 0. 只做一次的配置

把 [示例库](vault/CONTEXT.md) 复制到临时目录，安装 CtxKit 并准备 PyYAML。填好 [常驻指令模板](../skills/context-setup/assets/AGENTS.context.template.md) 的库、导航与 Python 路径，增量加入客户端实际加载的指令文件。

下面假设已启用相关项目的阶段写回、session 工作摘要与局部维护。这个前提不能只写在一条旧聊天中就假定所有新聊天都继承。

## 1. 自然接手一个项目

在新聊天中直接说：

```text
接着做 Atlas。先看看现在做到哪一步，列出中文和混合语言检索还缺哪些验证。
```

agent 应主动使用读取流程，定位导航与 Atlas 项目，得出：英文原型做过示例检查，中文仍待验证，尚未部署；再完成用户要求的缺口分析。

这里只读取和分析已有情况，没有新增已确认项目事实时，不为“读过了资料”修改笔记或创建 session。不能从历史下一步直接推断本次已获准部署。

## 2. 阶段有结果后主动记录

用户随后提供新信息：

```text
我刚测了，中文检索的 6 个样例通过，混合语言的 2 个样例失败。
还没有部署，下一步先排查混合语言分词。
```

无需额外说“记下来”。因为已启用阶段写回，agent 应增量更新 Atlas 的状态与相关检查记录，保留“用户反馈”的来源和实际记录日期。中文不再笼统标为未验证，混合语言失败和未部署状态仍保留。

随后创建或更新本会话的工作摘要，关联 Atlas，写明本阶段确认的结果与已写回位置。不能把用户测过写成 agent 亲自运行过；项目更新成功后才能在摘要里标记已写回。

## 3. 同一会话跨项目

继续说：

```text
另外，Beacon 本期栏目已经定成“进展、待决定、下周”，但运营数据还没到。
```

agent 应读取 Beacon 的已有背景，核对后更新对应项目，并在同一份 session 摘要中增加 Beacon 部分。这个会话最终关联 Atlas 与 Beacon 两个项目，不会仅因切换项目而新建另一份 session。

如果栏目已在项目中确认过，只补充真正新增的事实，不为了这条消息重复写一遍旧结论。一个项目写回失败时，摘要按实际结果说明未同步项。

## 4. 跨天继续，以及重复保存

第二天仍在同一来源会话中：

```text
混合语言的问题定位了，是预处理把连字符去掉造成的，修复还没开始。
```

agent 应继续同一记录，保留昨天的成果，增加定位结论，更新 `updated_at`，保持 ID 和文件名不变。只定位原因不代表已修复或已验证。

如果下一条没有新信息，重复确认相同内容不应改文件或刷新时间。上下文压缩后，优先通过真实来源身份或交接中保留的记录 ID 重新定位；缺少可靠映射时说明并确认，不凭标题猜测。

新聊天、分叉默认是新记录；只有明确接续旧记录时才延续其 ID。

## 5. 自然查询最近工作

```text
最近做了哪些事？只看 Atlas 相关的。
```

agent 查询摘要属性，按 `updated_at` 倒序筛选，需要细节时再读正文；不更新记录或导航时间。

发布的示例库中有 [跨项目会话](vault/sessions/sess_11111111111141118111111111111111.md) 和 [通讯跟进会话](vault/sessions/sess_22222222222242228222222222222222.md)。不筛选时 1 月 17 日的通讯跟进排在前面；筛选 Atlas 后，只剩关联两个项目的那一条。重新复制文件也不改变这个顺序。

## 6. 检查或局部整理

```text
Atlas 的当前状态里好像有矛盾，先检查一下，不要修改。
```

即使启用了日常维护，也应只报告具体矛盾和依据。这一轮的只读要求优先。

正常写回时如果发现“所有语言都未验证”的旧结论，且有充分证据与局部维护约定，可修正对应小节；不能顺手重写全部项目。主文档只保留接手所需状态与链接，详细论证移到相关专题，历史摘要仍保留历史性质。

## 7. 新项目和按需指定

```text
把这个新项目登记到上下文库，名称是 Cedar，目标是整理公开技术资料。
```

agent 选择接入流程，按真实资料创建项目入口并更新导航，未知信息保持待确认。日常回到已登记项目时无需再初始化。

只有想精确选择能力或排查匹配问题时，才需要诸如 `使用 $context-read，接着做 Atlas` 的写法。没有常驻写回约定时，仍可以临时要求“把这次成果保存下来”；安装 skill 本身不等于启用所有项目的持续写入。

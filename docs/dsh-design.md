# CtxKit DSH：知识与能力空间

## 已确认的产品方向

CtxKit 不再以旧版五个 skills 或项目记录格式为边界。用户正常在 DSH session 中工作，插件把实质成果整理成个人上下文库。项目只是主题的一种：长期事项、技术专题和工作方法也可以独立形成主题。

- 主题：`OVERVIEW.md` 是索引，`docs/` 承载详细知识，`skills/` 按需承载操作草稿。目录逐步生长，不预建空分类。
- Session：稳定身份的工作档案，入口概述与当前停点，阶段记录保存成果、决定、验证、失败和来源；不是聊天全文副本。
- 关系：同一 session 可贡献多个主题；关系包含类型、原因和依据，反向关系派生。语义相似只用于发现，不自动证明关系。
- Skill：可复用操作的草稿，有适用范围、前置条件、步骤、验证和失败处理。生成不等于安装，更不等于授权执行。
- 当前理解与历史分离。计划、实现、实测、用户反馈、推断不可混写。旧结论被修正时仍能追溯来源。

## MVP 范围

采用无数据库的 Node.js ESM 核心与独立 DSH Host bundle。旧版 Python skills 保留为独立的历史原型，不作为新模型依赖，也不自动迁移旧库。

自动链路是：新增回合事件 → 有界来源提取（仅内存）→ 阶段摘要 → session 工作档案 → 有界知识整理方案 → CAS 写回主题。两次模型调用都只生成文本/JSON，没有工具，也不能执行项目任务。用户须先确认已有库目录、当前工作目录范围及沿用会话模型的政策（兼容固定模型配置），且当前 session 文件权限允许写入，才开始自动处理。

第一版用回合结束作为候选检查点。模型可返回 `meaningful: false`，不会每轮创建阶段文件。不宣称能在一个尚未结束的长回合内保存，也不保证断电前保存；后续可增加阶段聚合和长回合检查点。

只观察启用后新发生的事件。持久任务仅包含会话/回合/序号和阶段状态，不包含原始聊天。已经保存的阶段可重试整理；尚未保存摘要的任务必须重新取得被授权的原始来源才能恢复，不能凭空补写。

## 数据契约 v1

Markdown 正文是知识内容的权威数据。第一行 `<!-- ctxkit {JSON} -->` 保存 schema、稳定 ID、类型、标题、来源和关系等机器可读元数据，不在另一个数据库重复维护正文。保留普通 Markdown 可读性；第一版只管理自己的标记文件，不覆盖已有无标记资料。

```text
vault/
├── INDEX.md                           # 可重建的主题导航
├── USER.md                            # 同库共享的当前用户偏好（非执行指令）
├── GLOBAL.md                          # 跨会话共享的最近已知状态，非用户习惯
├── topics/<topic-id>/
│   ├── OVERVIEW.md                    # 范围、当前理解和导航
│   ├── docs/<name>.md                 # 按需知识文档，可有子目录
│   └── skills/<name>/SKILL.md         # 惰性草稿，不安装不执行
├── sessions/<session-key>/
│   ├── SESSION.md                     # 概述、阶段导航、接续信息
│   └── checkpoints/<checkpoint-id>.md
└── .ctxkit/
    ├── jobs/                          # 来源标识、状态、错误；无原文
    └── transactions/                  # 可恢复的写入意图，不覆盖外部新修改
```

DSH session ID 经稳定哈希映射到目录，原 ID 保存为来源；fork 的不同原 ID 得到不同目录。Checkpoint ID 来自 session、回合和来源事件序号，同一回合重放不会生成新的记录。

### 阶段提取结果

- `meaningful`: 是否有新增可保留信息。
- `title`, `summary`, `next`: 本阶段标题、事实摘要、当前接续点。
- `facts[]`: `text`, `kind`（decision/result/failure/blocker/plan/correction）, `evidence`（observed/user_reported/inferred/planned）, `sourceSeqs[]`。
- `topicHints[]`: 主题名称线索，不是正式归属。

来源序号必须在输入提供的范围内。模型判断的证据类型仍需人工/实际评估，不把格式校验当事实正确性保证。

### 主题更新方案

- `topics[]`: 稳定 ID、标题、别名、范围及 OVERVIEW 正文；已有主题必须携带读取时的 revision。
- `documents[]`: 主题 ID、相对主题内路径、title/body、expectedRevision（新文档为 null）；仅允许 `docs/**/*.md` 与 `skills/<name>/SKILL.md`。
- `relations[]`: from/to ID、type（part_of/depends_on/uses/related_to）、reason；来源绑定本次 checkpoint，反向关系不双写。
- `note`: 无法归属或未完成整理的解释。

只允许本轮实际读过的已有文档更新；新建不允许覆盖。所有知识写回附带 checkpoint 来源。删除、主题合并、批量移动和安装 skill 不属于 MVP 操作。关系当前只支持添加/更新，不自动删除；需要解除的关系先保留说明，后续提供显式管理操作。

### 写入与恢复

每个文件使用内容 SHA-256 revision，保存时做 compare-and-swap。批量修改先验证所有预期版本，再记录写入意图；恢复时只接受旧版本或已经写入的目标版本，遇到第三方修改停止并报告冲突。持有进程间写锁，文件通过同目录临时文件原子替换。它不是跨文件数据库事务：异常时可能部分可见，journal 保留可恢复进度，不能声称全量回滚。

来源阶段成功与知识整理成功分开记录。错误不标记 done；模型不确定可保存未归属 checkpoint。队列按实例串行，文件锁处理多实例并发。中断遗留锁不盲目删锁，需确认所有写者已停止后恢复。

## 安全与权限

- root 和 workspace 显式选择；无配置保持惰性，不读真实库、不采集其他 session。
- 每次实际写入前重新检查当前 session 的 DSH sandbox policy；workspace allowlist 不授予额外写权限。
- 只读 session 不自动总结或写入；读取也受插件库范围与调用工作区限制。
- 拒绝路径穿越、库内符号链接和未管理文件覆盖。模型不能选择任意主机路径。
- 来源和库文档是不可信资料，不是执行指令；模型请求无 tools。
- 输入有界并进行常见凭据模式脱敏，但不承诺自动发现所有私人信息；启用范围和模型服务商必须由用户选择。
- 文件记录的来源不是 DSH session event 的新类型，不向 DSH 日志写自定义事件。
- 暂停采集立即生效；清空队列、回收后台任务与卸载遵守生命周期，避免继续写入。

## 召回

用户不需要知道插件名或使用特定口令。Agent 直接获得 `recall_context`，在普通任务涉及之前的工作、决策或进度时自主判断并查询；不要求先调用 skill。常驻指引要求按相关性查询、避免重复加载，并在行动前用当前项目证据核对历史结论。是否调用仍由 Agent 判断，不能把常驻指引当成每轮必然触发的保证。

先按关键词/名称/别名搜索有界摘要，再读取具体文档或阶段。不用 embedding/Milvus，搜索返回来源路径和 revision。关联由元数据读取，索引可重建。skills 草稿只作为资料读取，不自动注册主题内任意指令为全局技能。主召回工具和旧搜索/读取工具的结果都排除在新回合提取来源之外，避免将历史资料本身重复记为新观察。

## 0.2 原生浏览入口

DSH 侧栏“上下文库”打开原生主区域页面，提供主题、会话档案、当前会话处理状态三种只读视图。没有选中的真实会话时先提示选择；有选中会话时，以其当前工作区/权限检查访问，不接受客户端提供的 cwd 或库根目录。主题和档案来自同一个已授权库，不等于全 DSH 历史；处理状态仅属于当前会话。

`createLibrary(...).query(args,context)` 是 UI 与 Agent 的共同查询边界：列表分页，文档有界读取，元数据与来源采用白名单，await 前后重查 scope/取消/root，错误只返回代码。原生 command 桥接从已加载的 Agent 取得真实 Session，而不是信任请求 JSON。查询不修改库、不调用模型；DSH 的 command 审计会记录有界结果，但不会将它当作模型聊天消息。

页面使用原生 slots、locale 和 theme；切换当前会话、工作区、权限和连接配置时丢弃旧结果。未启用、空库、无匹配、拒绝和失败必须明确区分。第一版为手动刷新快照、安全纯文本正文和受管理的来源/关系导航，不提供任意 HTML/链接执行、编辑或权限提升。

## 0.6 原生目录窗口与 Finder

本轮用户确认浏览器和 DSH 在同一台 Mac。资料页点击目录按钮直接打开 macOS 系统选择窗口，不先列举文件夹，不使用浏览器上传目录冒充后台可写绝对路径。原生确认后沿用五字段原子接入；取消不保存。主界面移除文件树，提供“在 Finder 中打开”，Sessions 搜索保留。

浏览器通过同源 api/ctxkit-desktop/{pick,open} exact Fetch 入口调用，沿用 Connection 的 owner-only 门槛并额外拒绝 Authorization 头；不更改反向代理或新增服务器。路由内继续检查 browserPeer、owner、可写 Settings 与显式 global settings/update allow；不作为 agent command/tool，也不额外注册独立 RPC 或 WebServer 路由。选择器复用 DSH 官方 pickNativeDirectory，Finder 使用无 shell 的官方 runner，固定 open -a Finder，目标只能来自 Host 当前 root，客户端不接受路径参数。不修改 DSH 全局 directoryPicker。请求、连接与卸载取消会传到 native helper，选择器同一时刻只允许一个；失败不泄露进程 stderr，不声明保存成功。

默认 macOS-only；远程另一台电脑和无桌面场景不冒充支持。0.5 的有界 tree 查询仍保留给读取工具，但不再呈现网页文件浏览器。

## 0.5 资料页接入与文件树

直接在 Context Library 中显示“选择目录”入口，确认宿主已有目录后，原生 Settings 在一次带 revision 的更新中保存 root、enabled:true、allowedWorkspaces:[当前 cwd]、useSessionModel:true、exactWorkspaces:true。确认前显示当前工作目录与额外模型调用说明；没有独立的路径配置表单、第二个保存按钮或另行手填模型的步骤。已有旧版目录也能通过“使用此目录”完成接入。插件面板只引导到资料页。

这是用户授权动作，只通过原生 Settings 全局更新权限执行，不通过 Agent 工具或仅有 session command 权限的调用代写。取消/文件夹导航不改变设置。当前 cwd 必须来自所选真实会话，前端 scope-key 变化取消旧选择；Host 校验目录和完整运行时配置后再允许持久化。五个字段为同一原子提交，回执逐项检查，不将未知结果宣称成功。重新接入只启用当前 canonical cwd，不含嵌套独立工作目录、不自动迁移或删除旧库，也不修改 DSH 文件权限。

会话模型政策由 Host 在每次操作时从真实 Session 对应的 Agent.model.current() 解析。没有模型、采集关闭、会话暂停、只读或库不可写时不触发整理，不猜测默认路由、不通过重试恢复绕过限制。既有固定 provider/model 模式仍兼容。只读资料查询仅依赖库与授权范围，不再被采集开关或模型阻挡；尚未接入返回正常 setup_required，资料页显示引导而非反复报错。

默认“文件”页签显示可展开目录树，条目来自有界 tree 查询，按实际受管理 Markdown 路径构造层级；合法的 INDEX、主题、详细文档、草稿、会话档案和阶段文件均可查看，内部状态/无标记文件/符号链接不暴露。文件列表分页，保留扫描和响应上限，不自动全库加载。“Sessions”页签独立搜索已采集的会话档案，不等于全 DSH 历史列表。正文仍为只读安全文本。

配置生效时先取消旧查询、旧采集与缓存，再按完整新快照重建。存储选择、浏览和采集各自报告准确状态，安装或单纯打开页面不构成采集授权。

## 验收标准

使用虚构临时库验证：首次主题、同主题增量更新、跨主题 session、回放去重、无信息跳过、暂停/只读、来源范围、失败重试、过期 revision、journal 部分恢复、路径和符号链接拒绝、skill 草稿、双向关系查询、主进程卸载及 scope 隔离。模拟模型测试不证明真实模型提取准确率；真实 DSH 注册、真实 provider 和真实用户库分别报告验证状态。

## 0.7 库级用户偏好

USER.md 与 topics、sessions 并列；全局指同库已授权会话，不跨库、不扩大 workspace、文件或子代理权限。只从原生 `user/message` 且 `source.kind=user` 的本轮保留片段提取明确、持久、跨任务偏好。模型需给出对应 seq 和原文短引文，Host 校验精确匹配；工具/助手/注入消息不能伪造用户证据。语义是否真的属于长期偏好仍依赖模型判断，不把引用校验说成语义证明。

capture 的可选 preferences[] 使用稳定 pref_slug、set/remove、单段 text、sourceSeq、quote；最多六项。没有偏好仍兼容原输出。原文短引文只用于内存校验，任务不持久化 userSources/quote。阶段摘要、session 与偏好更新由同一 CAS/journal 批次提交，之后才进行主题整理；无第三次模型调用。

Markdown 正文保存当前偏好文本，首行 metadata 仅保存条目 ID、来源与时间。更正复用 ID；删除移出当前正文，仅保留无旧文本的 tombstone。入队时固定观察时间；旧任务的重试不能覆盖更新的同 ID 变更。32 个活动条目、64 个删除水位满时明确报错，不静默淘汰。无标记 USER.md、格式破坏或 revision 冲突不会被覆盖。可以保留结构修改正文，结构性增删应通过自然语言变更流程。

通过 DSH 原生 systemPrompt.context 注册同步、有界、scope-checked 的动态上下文：每次 admission refresh 只读这一个最多 128000 bytes 的文件，生成不足 8000 字符的 user-role 历史数据快照，由宿主记录；不注册高优先级用户指令，不修改 AGENTS 文件。内容与退役 ID 是不可信资料；当前请求和更高优先级规则优先，不能据此取得发布/支付/访问等权限。读失败只报告状态并省略该快照，不阻断主任务。只读或暂停采集不撤销已有库的读取授权。

删除偏好不是清除旧会话、checkpoint 或宿主此前注入的历史快照。新的快照声明只使用当前活动偏好，不复活历史已删除默认值。首次识别到明确偏好才生成文件；不会根据本次开发需求编造用户习惯。

## 0.8 全局共享状态

GLOBAL.md 独立于 USER.md：后者仅记录明确的用户习惯；前者记录同一授权库中跨会话有用的当前事实、共同约定、重要决策与未解决事项。具体项目实现、逐回合进度仍在主题和 session，不因为“可能被其他 session 读取”就全部提升为全局状态。用户也可明确要求将某项事实作为共享内容保留。

同一 capture 输出可选 globalState[]（最多六项），用 global_slug、set/remove、category、单段 text（最多600字符）和 factIndexes（指向本次验证过的 facts 数组）。Host 从这些事实派生事件序号与完整 evidence 标签集合，不能由变更自行伪造来源或将 planned/inferred 升为 observed。正文可读地标出类别、证据类型和记录时间；observedAt 仍是持久入队时点，不宣称事实恰在该时点发生。语义相关性和事实解释仍需模型及实际核查。

GLOBAL、USER、checkpoint、session 在同一 CAS/journal 批次发布；不加第三次模型调用。全局条目复用稳定 ID 更新或移除，32项活动内容、64项无旧正文的删除水位；旧/同时间任务不能覆盖更新记录。同内容重复确认推进来源和记录时间，证据类型变化也更新内容时间。未提及不自动删除；无新证据不从历史复活。删除当前项不抹去 checkpoint 或宿主旧快照。

两份根文件各自通过原生动态 user-role context 提供不足8000字符的快照，合计不足16000字符；不扫描整个库，不改系统级权限或项目指令。GLOBAL 显式为最近已知状态，不是实时健康检查；行动前复核时效性，约定/决策不能作为执行授权。读取复用同一单文件大小、scope、符号链接和取消边界。首次有来源更新才生成，不自动导入旧聊天或填入开发测试数据。

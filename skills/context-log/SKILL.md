# 记录会话工作

项目文档描述当前状态；会话记录描述这次工作做了什么。一个会话可以关联多个项目，跨多天仍维护同一条记录。记录成果、必要理由、证据链接和未解决事项，不复制完整聊天或工具输出。

## 阶段触发

生效指令已启用当前任务的会话记录时，阶段成果确认后主动执行，不等待用户说“保存 session”。在完成回复、切换工作或因新阻塞等待用户前更新已有摘要；无变化或用户要求只读、暂不记录时跳过。一次维护不再次触发自己，也不为每条消息建立记录。

记录 ID 应保留在当前会话的工作状态或交接摘要中。上下文压缩后先用真实来源身份或保存的记录 ID 恢复映射；没有可靠映射就按身份规则处理，不能承诺所有客户端都提供自动恢复能力。关闭窗口、强制中断或应用崩溃不是本 skill 能监听的事件。

## 定位和身份

- 优先使用用户指定的库入口，其次使用适用的 agent 指令，再考虑 `CONTEXT_ROOT`。没有配置时只检查已有 `~/context`；无法定位时询问，不新建另一套库。
- 先读库导航和相关项目入口，沿用其现有路径。只有用户要求记录或已有适用的阶段记录约定时才写入；查询不写文件。
- 能获取真实来源平台和会话 ID 时，用这两个值定位记录。不能用标题、日期、当前目录或“最近一条”猜测身份。
- 没有来源 ID 时，首次明确新建，并保留脚本返回的记录 ID；后续使用这个 ID 更新。丢失映射时列出候选，请用户确认，不自动合并。
- 新聊天或分叉默认是新记录。用户明确要求接续某条记录时，按该记录 ID 延续，不改它已保存的来源身份；可在正文标明后续接续来源。

## 使用脚本

使用本 skill 自带的 [records.py](scripts/records.py)。读取 [CLI 说明](references/cli.md) 获取环境准备、输入格式和具体命令。脚本依赖 Python 3.9+ 与 [PyYAML](requirements.txt)，无需其他 skills 或数据库。

- `get`：按记录 ID 或真实来源会话读取已有内容与 `revision`。
- `save`：创建记录，或提交完整的合并后正文。更新已有内容时带上刚读到的 `revision`；冲突就重读合并，不能用旧稿强行覆盖。
- `list`：按 `updated_at` 倒序，支持项目、来源与条数过滤，输出 Markdown 或 JSON。
- `view`：按用户需要添加可选 Obsidian Bases 视图；已有自定义视图不覆盖。

脚本负责 ID、日期、规范化项目链接、原子写入和来源去重。输入正文通过 JSON 文件或标准输入传递，不把用户原文拼接进 shell 命令。日期按实际保存时刻写入 UTC，不把示例时间作为当前时间。

## 整理内容

1. 新记录写简短目标或概览，再按项目归纳本次成果。
2. 更新前读取整条现有摘要，保留之前仍有意义的成果。只增加新阶段，合并重复表述；同一成果修正时标明变化，不把历史抹掉。
3. 区分计划、实现、验证、部署及用户反馈。工具没有执行过的检查不能写成已通过，用户提供的结果保留其来源。
4. 项目按库内完整路径关联，避免同名歧义。无对应项目可以使用空列表，不为凑字段编造项目。
5. 长期决策和当前状态属于项目文档。任务要求或已有授权包含项目写回时，更新对应文档，再在工作记录中添加实际写回位置；未写回时不能标成已同步。
6. 重复保存没有新信息就不改正文；脚本不会更新时间。仅查询、重建列表也不会把旧记录顶到最前。

这份记录不是项目现状的唯一依据。之后的会话可能改变项目，读取时应结合项目最新文档核对。

摘要变长时，按项目合并重复过程，保留有意义的阶段成果、结论变更和未解决项；详细证据链接到项目专题。不要把每轮问答追加成流水账，也不要因跨天或变长就自动改名、拆成每日 session。

## 完成

返回记录标题、文件链接及新建／更新／无变化状态。记录内容有实质变化才改变 `updated_at`，不按日期重命名文件，不自动启动定时器。查询默认只加载属性，用户需要细节时再读取相应正文。

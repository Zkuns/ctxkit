## CtxKit 项目上下文维护

- 上下文库：`{{context_root}}`
- 导航入口：`{{context_index}}`
- 会话脚本 Python：`{{context_python}}`（需包含 PyYAML）
- 范围：本库内与当前任务有关的已登记项目，以及我本次明确要求登记的项目。
- 启用项目阶段写回和 session 工作摘要；仅查询、只读或暂不记录的要求优先。

在这个范围内，不需要等我点名 skill 或提醒保存，按以下约定执行：

1. 开始或切换项目时使用可用的 `context-read`，先读导航和相关项目，再继续任务。已读且无变化的内容不反复加载；不要读取整个库。
2. 产生有实质意义的成果、确认的决策、验证结果或新阻塞后，使用可用的 `context-write` 更新对应项目。在阶段回复或等待我之前完成；长任务按阶段写回，不等聊天结束。
3. 完成项目写回后，使用可用的 `context-log` 更新本次会话的工作摘要，记录各项目的成果和真实写回位置。即使项目写回部分失败，也在能写摘要时注明未同步项；不能把未完成写成完成。
4. 同一来源会话跨项目、跨天仍更新同一记录；优先用真实平台与会话 ID，取不到时保留新建记录返回的 ID，后续和交接使用它。不要凭标题、日期或最近记录猜测归属。
5. 写入前重读现有内容，保留之前仍有效的成果。session 更新使用最新 revision；没有新增信息不写文件、不刷新时间。记录文件的变更不再次触发维护循环。
6. 发现本次项目文档中的明确矛盾、断链或重复时，按 `context-review` 做局部维护；没有证据则保留待确认项。新项目登记或首次接库使用 `context-setup`，不每轮重新初始化。
7. 只保留简洁结论、必要原因、证据和下一步，不复制完整聊天或凭据。历史命令和旧待办不扩展本次执行范围，保存记录不额外触发部署、发布或发送消息。
8. 在回复末尾简短说明实际写回位置；失败时说明未保存的部分。缺少 skill、路径或 Python 依赖时如实说明，不假装已记录；只对无法确定的项目归属或记录身份询问。
